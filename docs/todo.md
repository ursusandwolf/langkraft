# Langkraft Development Roadmap

## Ближайшие спринты

Цель: пройти сценарий «вставить YouTube URL → импортировать контент → слушать с субтитрами → сохранить слово → увидеть контент и слово после перезапуска».

Первая платформа — Web. Спринты выполняются в порядке 1–5; Android перенесён на финальную стадию после Web-версии. Спринты 1–3 завершены: репозитории, Web-интерфейс и настоящий YouTube-импорт проверены. Workflow спринта 4 (CI) реализован; остаётся подтвердить первый запуск на GitHub из чистого checkout. Затем — спринт 5 (обработка субтитров). Даты и длительность не назначены.

### Спринт 1. Реализовать репозитории

- [x] Реализовать `ContentRepository`: наблюдение за библиотекой, чтение контента с субтитрами по ID, сохранение и обновление.
- [x] Реализовать `VocabularyRepository`: выборка слов для повторения, сохранение, обновление и удаление.
- [x] Подключить SQLDelight и создание драйверов Android/JVM; включить внешние ключи. Android-фабрика пока не проверена сборкой из-за отсутствующего SDK.
- [x] Сохранять контент и его субтитры атомарно, сохраняя ссылки слов и уже записанный прогресс SRS при обновлении.
- [x] Подключить HTTP-клиент к `POST /api/ingest`: передавать URL, читать ответ, обрабатывать ошибки и отмену запроса.
- [x] Реализовать загрузку и файловое хранение аудио для Android/JVM: обновлять локальную ссылку после успешного завершения, удалять незавершённую загрузку при ошибке или отмене.
- [x] Добавить тесты репозиториев с настоящей SQLite и HTTP-заглушками, включая повторное открытие базы.
- [x] Выбрать Web первой платформой; перенести Android на финальную стадию.
- [x] Перевести SQLDelight и общие репозитории на асинхронное выполнение, сохранив JVM-тесты.
- [x] Добавить Web worker с SQLite/WASM и постоянным IndexedDB-хранилищем базы, включая внешние ключи и версию схемы.
- [x] Добавить потоковое IndexedDB-хранение аудио и восстановление временного URL для плеера после перезагрузки.
- [x] Подтвердить готовность Web-хранилища браузерными тестами Kotlin и проверкой перезагрузки страницы.

**Проверено:** 39 JVM-тестов, 23 Kotlin-теста в headless Chromium и 3 отдельных браузерных сценария для перезагрузки/отката/неполного аудио. Настоящий импорт YouTube остаётся задачей спринта 3.

**Критерии готовности:** импорт через `IngestContentUseCase` сохраняет метаданные, субтитры и ссылку на локальное аудио; повторное открытие базы возвращает контент и сохранённые слова; обновление не разрушает связи и SRS; ошибка загрузки оставляет доступным ранее сохранённый удалённый контент. Тесты проверяют изменения `Flow`, выборку по сроку повторения, удаление слова, ошибки HTTP и отмену операций.

### Спринт 2. Добавить запускаемое Web-приложение

- [x] Выбрать Web первой платформой запуска.
- [x] Добавить модуль Web-приложения, точку входа и сборку зависимостей репозиториев, аудиоплеера и `PlayerViewModel`.
- [x] Добавить экран библиотеки с состояниями загрузки, пустого списка и ошибки.
- [x] Добавить ввод YouTube URL, состояние импорта, сообщение об ошибке и повторную попытку.
- [x] Подключить открытие контента, воспроизведение, перемотку, перевод и сохранение слова; освобождать плеер при завершении его жизненного цикла.
- [x] Добавить экран слов для повторения, dev proxy `/api` и [инструкцию запуска](WEB_APP.md).
- [x] Проверить development- и production-сборки в Chromium: ошибка/повтор импорта, воспроизведение, сохранение слова, освобождение плеера, восстановление библиотеки/слова после перезагрузки и локальное аудио при заблокированном API.

**Проверено:** production-сборка, 39 JVM-тестов и 23 Kotlin-теста браузера проходят. Сценарий интерфейса использует локальный тестовый API с WAV-аудио; настоящая загрузка YouTube относится к спринту 3. Перевод — демонстрационный. Аудио работает без backend в открытом приложении; офлайн-запуск самой страницы/PWA пока не реализован.

**Критерии готовности:** приложение запускается документированной командой на выбранной платформе; пользователь проходит основной сценарий; после перезапуска видит библиотеку и сохранённое слово. Локально сохранённое аудио воспроизводится без сети на выбранной платформе. Перевод пока может использовать существующую mock-реализацию.

### Спринт 3. Проверить настоящий импорт YouTube

- [x] Подготовить окружение с `yt-dlp`, `ffmpeg` и `ffprobe` для проверки Web-версии.
- [x] Проверить импорт реального видео с немецкими субтитрами и согласованность метаданных, аудиофайла и URL раздачи.
- [x] Проверить воспроизведение и перемотку с HTTP Range в приложении из спринта 2.
- [x] Проверить отсутствие немецких субтитров, недоступное видео, неверную ссылку, таймаут и отмену импорта.
- [x] Зафиксировать команды, версии инструментов и результаты ручной проверки в [YOUTUBE_VERIFICATION.md](YOUTUBE_VERIFICATION.md).
- [x] Исправить отмену при разрыве HTTP-соединения, передачу отмены через dev proxy и очистку процессов/журналов на Windows; добавить регрессионные тесты.

**Проверено 21.10.2026:** Easy German 1 — 156,2005 секунды Opus-аудио, 48 строк субтитров, воспроизведение из IndexedDB, переход к строке и HTTP Range 206. Настоящие HTTP-проверки ошибок и отмена из Web не оставляют файлов. Таймаут проверен на управляемом настоящем дочернем процессе с лимитом 2 секунды; десятиминутный production-таймаут на YouTube не выжидался. JVM-регрессия — 43 теста. Сетевые тесты запускаются отдельно от обычного набора.

**Критерии готовности:** реальное видео импортируется и воспроизводится с субтитрами; перемотка работает; при неудаче пользователь получает понятную ошибку, а частичные файлы удаляются. Зависимость ручной проверки от доступности видео описана отдельно от автоматических тестов.

### Спринт 4. Настроить CI

- [x] Добавить автоматическую проверку pull request и изменений основной ветки.
- [x] Запускать JVM-тесты общего модуля и бэкенда, компиляцию JavaScript и браузерные тесты Web-хранилища. Android-проверки добавить на финальной стадии.
- [x] Проверять сборку приложения, добавленного в спринте 2.
- [x] Сохранять отчёты о тестах и использовать кэш зависимостей.
- [x] Выполнять автоматические тесты без обращений к YouTube и без AI-ключей.

**Реализовано:** [GitHub Actions CI](../.github/workflows/ci.yml), отдельные JVM/Web jobs, Kotlin-тесты в Chromium, сценарии хранилища и development/production-приложения, кэш Gradle/npm, отчёты и снимки экрана на 14 дней. Команды локального запуска перечислены в [README](../README.md#continuous-integration). Первый запуск на GitHub из чистого checkout ещё предстоит; до него приёмка спринта остаётся открытой.

**Локально проверено 2026-10-21:** Windows, JDK 21, Node.js 24.20.0; 43 JVM-теста, 23 Kotlin-теста в Chromium, три сценария хранилища и полный сценарий приложения на development/production-бандлах. YAML workflow проверен парсером. Исправлено зависание теста отключения клиента при остановке Netty. В CI development/production собираются отдельными вызовами Gradle из-за общих каталогов вывода Kotlin 1.9. Среда GitHub Ubuntu 24.04 / Node.js 22 ещё не проверена.

**Критерии готовности:** CI воспроизводит проверки из чистого checkout, показывает отчёты и завершается с ошибкой при падении теста или сборки. В README перечислены команды для локального запуска этих же проверок.

### Спринт 5. Усилить обработку субтитров

- [ ] Покрыть SRT с LF/CRLF, BOM, многострочным текстом и разным количеством пустых строк.
- [ ] Добавить валидацию индексов, временных меток, усечённых блоков и интервалов, где конец раньше начала.
- [ ] Определить и проверить обработку перекрывающихся и несортированных реплик, пустых файлов и отсутствующих немецких субтитров.
- [ ] Зафиксировать поддержку VTT: преобразование в SRT на этапе импорта либо отдельный парсер с тестами.
- [ ] Проверить, что ошибка разбора не сохраняет частично импортированный контент и очищает файлы неудачного импорта.

**Критерии готовности:** корректные файлы дают ожидаемые тексты и миллисекундные интервалы; некорректные файлы приводят к контролируемой ошибке без случайного выхода за границы массива. Все перечисленные случаи покрыты регрессионными тестами.

## Дальнейший roadmap и выполненная основа

Разделы ниже сохраняют продуктовые направления. Ближайший порядок реализации и критерии готовности определены спринтами выше; AI, полноценный SRS и полировка интерфейса идут после основного сценария.

### Финальная стадия: Android

- [ ] После завершения Web-версии установить Android SDK и включить цель через `-PenableAndroid=true`.
- [ ] Проверить Android-фабрику базы, общее файловое хранилище и асинхронные репозитории Android-сборкой.
- [ ] Добавить Android-приложение, проверить импорт, воспроизведение, офлайн-доступ и жизненный цикл на устройстве или эмуляторе.
- [ ] Добавить Android-проверки в CI и собрать APK/Bundle.

До этой стадии Android-плагин и SDK не требуются для обычной сборки и Web-проверок.
