# Backend media retention — REL-13

До REL-13 сервис удалял только старые строки IngestionJobs. Неиспользуемый DownloadCleanup не учитывал вложенные job-каталоги, активные импорты и HTTP-выдачу. Сетевые audioUrl остаются в клиентской библиотеке, поэтому включение TTL меняет срок доступности аудио.

## Решение

BackendModule создаёт один BackendMediaStorage для YtdlpClient, YouTubeIngestionService и mediaRoutes. **Один процесс backend владеет одним downloads_dir и БД**; совместное использование каталога несколькими процессами не поддерживается. Import/read leases и уборка сериализованы одним monitor. Межпроцессные leases требуют отдельного протокола и не имитируются TTL.

Импорт получает lease и новый UUID-каталог до записи задания в очередь. В каталоге создаётся `.langkraft-media-v1` с состоянием pending и timestamp. Lease защищает queued job, metadata, загрузку, парсинг и waveform. Публикация под monitor записывает ready со временем публикации, выполняет callback записи READY в БД и открывает чтение. HTTP-читатель не увидит промежуток между READY и освобождением import lease; при ошибке callback импорт остаётся защищённым и недоступным для чтения до компенсации. Успех, ошибка и shutdown освобождают lease; обработанная ошибка удаляет только принадлежащий импорту каталог. После перезапуска pending с истёкшим сроком удаляется по принятой модели одного владельца.

`storage.media_retention_ms` / `LANGKRAFT_MEDIA_RETENTION_MS` — неотрицательное число миллисекунд, **0 по умолчанию выключает удаление**. Очистка запускается при инициализации ingestion service и затем с `ingestion.cleanup_interval_ms`. Для ready срок отсчитывается от публикации, для abandoned pending — от постановки в очередь. Чтение не продлевает TTL.

Удаляются только распознанные UUID-каталоги с корректной меткой нового протокола и без import/read lease. Legacy, неизвестные/повреждённые метки и деревья с symlink сохраняются. Ошибки удаления логируются и возвращаются в CleanupResult; метка удаляется последним файлом, при отказе удаления финального каталога восстанавливается для повтора. Каталог принадлежит backend: внешние процессы не должны менять его во время работы.

MediaRoutes выдаёт новые managed MP3 через GET/HEAD. Legacy URL без метки сохраняют выдачу MP3/OGG/Opus/WAV/M4A, включая одноуровневые пути. Служебные файлы, неполные импорты и пути вне downloads_dir не выдаются. GET использует respondFile и PartialContent, сохраняя Range/416. Read lease удерживается через send pipeline и освобождается при успехе, ошибке или отключении клиента. Проверено настоящим Netty/CIO с 32 МиБ и обратным давлением. [Документация Ktor о выдаче файлов](https://ktor.io/docs/server-responses.html).

После TTL сетевое воспроизведение и новая offline-загрузка получают 404. Пользователь должен скачать offline-копию до истечения срока или импортировать источник заново. Клиентские метаданные и уже сохранённые локальные Web/Desktop/TUI-копии не меняются. Срок жизни polling-записи настраивается независимо через job_expiry_ms; cleanup БД теперь удаляет только READY/ERROR, сохраняя активную очередь.

## Варианты и компромиссы

- Возраст файла без протокола проще, но не доказывает владение и может удалить legacy или активный импорт.
- Маркер и единый реестр leases выбраны для текущего процесса backend: проверяемое владение и защита потоков без изменения схемы БД. Работа нескольких backend над общим каталогом не поддерживается.
- Квоты с резервированием нужны дополнительно: TTL не ограничивает пик диска. Общий бюджет, byte-limit и остановка процессов при превышении остаются следующим этапом.

## Проверки

BackendMediaStorageTest: TTL от публикации, выключенное удаление, активный import, несколько readers, идемпотентное освобождение, restart/pending, legacy/unknown, частичный отказ и повтор, пути и symlink. На Windows без привилегии создания symlink соответствующий тест пропускается.

MediaRoutesTest: GET/HEAD/Range/416, 404 после TTL, служебные пути, медленная Netty-выдача и отключение клиента. IngestionAdmissionTest: периодическая уборка сохраняет queued/active jobs и каталоги, shutdown их освобождает. IngestionJobRepositoryTest: возраст не удаляет DOWNLOADING_AUDIO.
