# Обработка субтитров

Backend принимает немецкую дорожку, которую yt-dlp сохраняет как `<id>.de.srt`. Опции `--sub-format srt/best --convert-subs srt` выбирают SRT либо преобразуют доступный формат, включая VTT, через FFmpeg. Сам `SrtParser` читает только SRT: исходный VTT без преобразованного SRT считается неудачным импортом. Английская дорожка не заменяет отсутствующую немецкую.

## Правила SRT

- Поддерживаются LF, CRLF и CR, необязательный BOM в начале файла, начальные и завершающие пустые строки, а также несколько пустых строк между блоками. Строки из пробелов/табуляций считаются пустыми.
- Индекс — положительное целое в пределах `Long`, строго больше предыдущего индекса в файле. Пропуски номеров допустимы; повторы и убывание отклоняются. Индекс не используется как ID реплики.
- Время имеет формат `HH:MM:SS,mmm`; для совместимости также принимается точка перед миллисекундами. Часы содержат не менее двух цифр, минуты и секунды находятся в диапазоне 00–59, миллисекунды содержат ровно три цифры. Пробелы и табуляции вокруг `-->` необязательны.
- Время вычисляется целочисленно в миллисекундах. Переполнение `Long`, отрицательные значения, нулевой и обратный интервалы отклоняются.
- В блоке обязательны индекс, временной интервал и непустой текст. Многострочный текст объединяется пробелами; внешние пробелы каждой строки удаляются. HTML-разметка не интерпретируется парсером. Между блоками обязателен пустой разделитель; временная строка внутри текста считается признаком отсутствующего разделителя.
- Реплики возвращаются по возрастанию начала. При одинаковом начале сохраняется исходный порядок. Перекрывающиеся реплики сохраняются с исходными текстами и интервалами, без слияния и обрезки.
- Репозиторий сохраняет порядок списка в `SubtitleLine.ordinal`; библиотека и плеер одинаково сортируют по `startMs, ordinal, id`. Миграция БД 1 → 2 сохраняет данные и связи слов. Для старых реплик исходный порядок одинаковых начал неизвестен: до следующего сохранения используется сортировка по ID.
- Пустой файл, BOM без текста и некорректный блок вызывают `SubtitleParseException` с номером строки. Частичный список реплик не возвращается.

## Неудачный импорт

`YouTubeIngestionService` завершает разбор до формирования ответа с контентом. Ошибка разбора превращается в `IngestionException`; HTTP-клиент получает 502 с общим сообщением об ошибке импорта. Скачанные файлы этого импорта, включая аудио, субтитры и метаданные, удаляются. Файлы предыдущих успешных импортов сохраняются.

Клиентский `ContentApi` отклоняет 502 до чтения контента. `IngestContentUseCase` возвращает ошибку, не сохраняет новые строки в SQLite и не запрашивает аудио; ранее сохранённая библиотека остаётся доступной. Ошибка последующей загрузки аудио — отдельный сценарий: уже полученные корректные метаданные остаются в библиотеке, как описано в [DATA_LAYER.md](DATA_LAYER.md).

## Проверка

Обычная регрессия не требует FFmpeg, yt-dlp, YouTube или AI-ключей:

```shell
bash ./gradlew --no-daemon :backend:test :shared:desktopTest
```

В Windows используйте `.\gradlew.bat` вместо `bash ./gradlew`. `SrtParserTest` покрывает форматы строк, точность времени, сортировку, перекрытия и некорректные блоки. `IngestionTest` проверяет настройки преобразования, чтение преобразованной фикстуры, отказ при отсутствии немецкого SRT, очистку файлов и HTTP 502. `IngestionRepositoryTest` проверяет, что отказ backend не меняет клиентскую библиотеку и не запускает скачивание аудио. Эти наборы входят в существующий CI.

Фикстуры `backend/src/test/resources/subtitles/german.vtt` и `german.srt` проверены настоящим FFmpeg 9.0.2 локально, без сети. Обычные тесты используют уже преобразованный SRT и проверяют границу с yt-dlp; сам процесс преобразования не запускается в CI. Для повторения реального преобразования из корня проекта (с FFmpeg в PATH):

```shell
ffmpeg -hide_banner -loglevel error -y -i backend/src/test/resources/subtitles/german.vtt german-converted.srt
```

Сравните `german-converted.srt` с фикстурой `german.srt`, игнорируя только различия LF/CRLF и завершающие пустые строки. Должны совпасть два текста и интервалы 1001–3500 и 2500–4000 мс. В Windows локальная установка из [YOUTUBE_VERIFICATION.md](YOUTUBE_VERIFICATION.md) позволяет использовать `.\tools\media\build\ffmpeg.exe`.
