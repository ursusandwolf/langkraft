# Необязательный AI

Без переменных AI backend использует `AI_PROVIDER=none`. Импорт видео, аудио,
немецкие субтитры, ручной словарь и Review работают без AI. Для импорта
YouTube нужен интернет. Локальная Ollama выполняет автоматический перевод,
анализ и проверку письма без облачных ключей; для вызовов через backend нужен вход в Account.

Нажатие слова открывает карточку с контекстом и редактируемым переводом. Без AI
перевод вводится вручную. При включённом AI запрашивается подсказка; введённый
пользователем текст не заменяется запоздавшим ответом. Карточку можно сохранить
даже во время запроса или после ошибки. Пустой перевод сохранить нельзя.
Сохранённые переводы и SRS не зависят от наличия ключа.

`GET /api/ai/capabilities` — публичный запрос, возвращает `enabled` и имя
провайдера (либо null). Ключи и модель клиенту не передаются. В отключённом режиме
защищённые AI-операции отвечают HTTP 503; mock-ответов в рабочем backend нет.
При недоступности backend клиент оставляет ручной ввод и локальное воспроизведение.

## Настройка backend

| AI_PROVIDER | Ключ | Протокол |
| --- | --- | --- |
| `none` (по умолчанию) | Не нужен | AI отключён |
| `ollama` | Не нужен | Native Ollama `/api/generate`, локальная установленная модель |
| `gemini` | `GEMINI_API_KEY` | Gemini generateContent |
| `claude` | `ANTHROPIC_API_KEY` | Anthropic Messages, версия 2023-06-01 |
| `openai` | `OPENAI_API_KEY` | Chat Completions, также совместимые серверы |

Для включённого провайдера обязательна `AI_MODEL`: точный идентификатор установленной
локальной модели либо модели облачного аккаунта. Модель не закрепляется в коде. Один ключ без выбора
провайдера AI не включает. Неизвестный провайдер, отсутствующие ключ/модель — ошибка
конфигурации, без перехода к тестовым ответам.

Локальный запуск в PowerShell после установки Ollama и модели:

```powershell
ollama list
$env:AI_PROVIDER = 'ollama'
$env:AI_MODEL = 'qwen3.5:2b' # пример; модель должна присутствовать в ollama list
$env:AI_BASE_URL = 'http://127.0.0.1:11434' # это также значение по умолчанию для Ollama
# LANGKRAFT_JWT_SECRET уже настроен по RUNNING.md
./gradlew.bat :backend:run
```

Если daemon не запущен, выполните `ollama serve` в отдельном терминале.
Приложение не запускает Ollama и не скачивает модели. Нет автоматического fallback
в Gemini/Claude/OpenAI. В Docker localhost означает контейнер backend: настройку
связи с хостом нужно выполнить отдельно; обычный HTTP разрешён только loopback.
При остановленной Ollama или отсутствующей модели AI вернёт 503, ручной ввод остаётся доступен.
Capabilities показывает настроенного провайдера; это не health check daemon и модели.

Для отключения: `AI_PROVIDER=none`, затем перезапустить backend и открыть материал
заново. Файл `.env` автоматически не читается. `AI_BASE_URL` необязателен и задаёт
корень API с версией (например, `https://api.anthropic.com/v1`). Для локального
сервера разрешён HTTP на localhost/127.0.0.1/[::1]. URL не может содержать
userinfo, query или fragment. Настройки
находятся только на backend; ключи не передаются в браузер.

## Strategy

```text
UI → RemoteLinguisticAssistant → backend
    ├─ none → DisabledLinguisticAssistant
    └─ enabled → CachingLinguisticAssistant
                 → StrategyLinguisticAssistant (общие языковые задачи)
                    → TextGenerationStrategy
                       ├─ GeminiTextGenerationStrategy
                       ├─ ClaudeTextGenerationStrategy
                       ├─ OpenAiTextGenerationStrategy
                       └─ OllamaTextGenerationStrategy → локальная Ollama
```

`GenerationRequest` передаёт промпт и необязательную JSON Schema. Стратегия отвечает
за формат HTTP-запроса, авторизацию и извлечение текста.
Промпты и разбор общих результатов находятся в `StrategyLinguisticAssistant`.
Новый несовместимый API подключается новой реализацией `TextGenerationStrategy`
и веткой выбора в `createLinguisticAssistant`; UI, словарь и SRS не меняются.
Поддержка произвольного API не означает совместимость без адаптера. Совместимые
с Chat Completions серверы можно подключать через `AI_BASE_URL`.

Ollama получает `stream=false`, `think=false`, temperature 0 и максимум 4096 выходных
токенов. Структурированные задачи получают `format` с JSON Schema; перевод предложения —
обычный текст. Схемы принадлежат языковым задачам. JSON дополнительно декодируется в DTO
и проверяется на обязательное содержимое. Исходный текст CorrectionResult берётся из запроса.
Обрезанный, пустой или повреждённый ответ не сохраняется. Качество языка оценивает пользователь.

| Ограничение Ollama | Значение по умолчанию | Переменная backend |
| --- | --- | --- |
| Полный бюджет генерации и чтения ответа | 120000 мс, допустимо 1–120000 | `AI_TIMEOUT_MS` |
| Одновременные разные генерации | 1, допустимо 1–16 | `AI_MAX_CONCURRENT_REQUESTS` |
| Размер тела ответа | 1048576 байт, допустимо 1–4194304 | `AI_MAX_RESPONSE_BYTES` |

Ожидание свободного слота не создаётся: перегрузка сразу возвращает 503 + Retry-After.
Одинаковые одновременные запросы разделяют одну генерацию. Отмена ожидающего клиента не
отменяет её для остальных; отмена инициатора отменяет общий запрос, допускается повтор.
Ошибка не кэшируется. Кэш каждой задачи живёт 10 минут и ограничен 1000 записями и
8 MiB оценённого payload (ключ + сериализованный результат), без учёта накладных расходов JVM.
Новый provider/model создаёт новый экземпляр кэша при перезапуске backend.

Вход — до 12000 символов текста/контекста, слово — до 256 символов. У shared AI-запросов
бюджет 150 секунд, отдельно от общего HTTP timeout 30 секунд. Backend HTTP client закрывается
при остановке приложения и не следует редиректам. Ошибки: 400 — неверный ввод,
503 — выключенный/недоступный/перегруженный AI, 504 — timeout, 502 — плохой ответ upstream.
Тела ошибок провайдера и ключи не передаются клиенту; автоматических повторов нет.

## Проверки

Backend проверяет конфигурацию и четыре протокола, схемы Ollama, авторизацию,
ограничения ответа/входа/конкурентности, TTL/LRU/single-flight, ошибки и отмену через MockEngine.
`npm run test:manual` в `tools/web-storage-tests` проверяет полный путь
слово → ручной перевод → сохранение → Review → перезагрузка как без AI и входа,
так и при ошибке настроенного AI. `npm run test:app` проверяет успешную подсказку.
Дополнительно проверяется, что поздняя подсказка не заменяет ручной перевод.
Эти тесты не подтверждают доступность конкретной модели или качество живого AI.

Опциональный интеграционный smoke использует отдельную временную backend БД и настоящую
Ollama, выполняет все четыре задачи через JWT-защищённые маршруты. Модель должна быть уже
установлена, иначе тест не скачивает её и завершится ошибкой. Без переменной тест пропускается:

```powershell
$env:LANGKRAFT_OLLAMA_LIVE_MODEL = 'qwen3.5:2b'
./gradlew.bat :backend:test --tests '*OllamaLiveTest' --rerun
Remove-Item Env:LANGKRAFT_OLLAMA_LIVE_MODEL
```

Проверка 2026-10-29: Ollama 0.40.11, установленная `qwen3.5:2b`, все четыре маршрута
прошли через реальную JWT-авторизацию и временную SQLite БД. Первый прогон:
слово 11.7 с, предложение 0.4 с, разбор 8.4 с, коррекция 2.8 с. Это измерения одного
локального прогона, не SLA и не общая оценка качества модели.
