# ADR-001: dev как основа, общая схема данных и async Repository

Статус: принято в интеграционной ветке, 2026-10-22.

## Контекст

В dev больше функциональности (SRS, sync, Desktop/TUI), main содержит отдельную Web-реализацию и исправления надёжности. Обе ветки независимо использовали версии схемы 1/2 с разными столбцами. Выбор одной стороны при merge потерял бы часть работы.

## Варианты

1. Заменить dev целиком кодом main: проще Web, но теряются SRS, auth, sync и Desktop/TUI.
2. Оставить синхронный SQLDelight dev и добавить отдельный Web-слой: два Repository с расходящимся поведением и риск потери данных.
3. Сохранить dev и адаптировать исправления/async-хранилище main: больше работы сейчас, один домен и общий UI/Repository для платформ.

## Решение

Выбран вариант 3. Общая схема v3 распознаёт фактические столбцы старой БД до изменения; обычного выбора номера `.sqm` недостаточно из-за совпавших версий обеих веток. Инициализация транзакционная; Desktop делает VACUUM INTO backup. У новых схем более высокой версии нет автоматического reset.

Один DatabaseAccess с Mutex координирует async-операции. Web SqlDriver — Adapter к worker/SQLite WASM, Desktop SqlDriver владеет одним JDBC-соединением и закрывает его. Repository не меняют SRS/словарь при повторном импорте. Отсутствующие локально source references сохраняются отдельно и восстанавливаются при импорте.

## Последствия

Платформы используют общий UI и правила целостности. Цена — async API для JDBC и отдельные проверки жизненного цикла соединения. Откат к старому main требует восстановления backup, а не только checkout. Квоты медиа, несколько вкладок и Android остаются отдельными задачами.
