# Legacy/no-lock: аудит и восстановление в копию

Наличие старого DOWNLOADING, `.part` или manifest без протокола не доказывает завершения владельца. Старая вкладка/версия приложения может не использовать новый lock; TTL/PID не дают достаточной гарантии. Поэтому startup recovery сохраняет legacy/no-lock и неизвестные форматы. Автоматическое удаление старых объектов не включается.

Для Desktop/TUI доступна [утилита recovery](../tools/recovery/recover_legacy_profile.py): Python 3.10+, только стандартная библиотека. По умолчанию она выполняет read-only аудит. `--clone-to` создаёт отдельный восстановленный профиль, не изменяя SQL-данные и аудио исходного профиля. Это выход из зависшего состояния через изолированную копию, а не подтверждение отсутствия живого старого владельца.

## Аудит

Из корня проекта в PowerShell:

```powershell
$sourceProfile = Join-Path $env:USERPROFILE '.langkraft'
python tools/recovery/recover_legacy_profile.py --source $sourceProfile
```

Для настроенного LANGKRAFT_DATA_DIR передайте его фактический каталог. JSON содержит версию схемы, зависшие Content, метки протокола и инвентаризацию непосредственных записей `audio/`; состояние владельца остаётся unknown. Содержимое journal не интерпретируется, токен аккаунта не выводится. Ссылки/подкаталоги не обходятся рекурсивно. Отчёт — наблюдение, а не разрешение удалить перечисленные объекты.

## Изолированное восстановление Desktop/TUI

Назначение должно быть новым и не пересекаться с исходным профилем:

```powershell
$recoveredProfile = Join-Path $env:USERPROFILE '.langkraft-recovered'
python tools/recovery/recover_legacy_profile.py --source $sourceProfile --clone-to $recoveredProfile
$env:LANGKRAFT_DATA_DIR = $recoveredProfile
.\gradlew.bat :shared:run --args=--smoke
.\gradlew.bat :shared:run
```

Для TUI используйте `:shared:runTui`. В Bash:

```bash
python3 tools/recovery/recover_legacy_profile.py --source "$HOME/.langkraft" --clone-to "$HOME/.langkraft-recovered"
LANGKRAFT_DATA_DIR="$HOME/.langkraft-recovered" bash ./gradlew :shared:run --args=--smoke
```

Утилита делает следующее:

1. Открывает исходную SQLite с mode=ro/query_only и создаёт согласованный snapshot через SQLite backup API, включая committed WAL. Схема проверяется до и после снимка; версии новее v3 отклоняются.
2. Переносит только связанные готовые обычные файлы внутри исходного `audio/`. `.part`, sidecar, внешние и отсутствующие пути не копируются. Общий файл копируется один раз; отчёт содержит размер/SHA-256. Изменение размера, mtime или identity во время копирования отклоняет файл.
3. Переписывает localAudioPath на новый профиль. DOWNLOADING становится COMPLETED при успешно перенесённом старом аудио, иначе ERROR с пустым путём. Недоступное аудио других статусов также становится ERROR только в копии.
4. Сохраняет остальные таблицы: субтитры, словарь/SRS, теги, pending sync, source references и курсоры. Удаляет auth_token и старые audio_download_lock метки только в копии. Схема не мигрируется утилитой; старую поддерживаемую схему обновит приложение при первом запуске копии.
5. Проверяет SQLite quick_check, сохраняет recovery-report.json и публикует готовый каталог. Существующий профиль не перезаписывается. При ошибке назначения нет, временный `.preparing-*` каталог сохраняется с путём в ошибке; его нельзя считать завершённым профилем.

Исходный процесс может продолжать работу: SQL-снимок согласован, а меняющиеся/исчезнувшие audio отмечаются недоступными в копии. Дальнейшие изменения исходного профиля после снимка в копию не попадают. Это не атомарный снимок SQLite и всей файловой системы.

Сначала проверьте словарь, очередь повторений, библиотеку и offline-аудио в копии без входа в аккаунт. Затем выберите профиль для дальнейшей работы и авторизуйтесь в нём. Исходный профиль и его сессия остаются доступны; оригинал утилита не удаляет.

## Web legacy/no-lock

Python-утилита не работает с браузерным IndexedDB. Для старых/неизвестных manifest и окружений без Web Locks сохраняется политика без автоматического сброса/удаления. Восстановление нового протокола работает через [lease и pending](ADR_AUDIO_DOWNLOAD_RECOVERY.md); отсутствие Web Locks можно устранить запуском приложения в поддерживаемом secure context, но это само по себе не делает старые записи безопасными кандидатами GC.

Отдельный Web export/copy recovery остаётся backlog. Очистка site data уничтожает библиотеку и не является способом безопасного восстановления. Общая retention подтверждённого/legacy-аудио также остаётся отдельной задачей.

## Проверка утилиты

```powershell
python -W error::ResourceWarning -m unittest discover -s tools/recovery/tests -v
```

Тесты проверяют read-only аудит, активного WAL-писателя, SRS/очередь/общие audio, очистку сессии только в копии, недоступные пути, нестабильный файл, смену версии схемы во время snapshot, отказ записи и запрет перезаписи назначения. Они подключены к JVM job CI отдельно от Gradle-тестов.
