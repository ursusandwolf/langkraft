# Changelog

Изменения записываются по мере выполнения. Новые записи до коммита относятся к `Unreleased`; номер версии не присваивается автоматически. Каждая запись содержит ID, поведение, проверку и ссылку на [UML-ченджлог](docs/CHANGELOG_UML.md) с тем же ID. В UML отражаются реальные классы и используемые паттерны; для изменений документации отмечается, что классы не менялись. Планируемая работа остаётся в [спринтах](docs/todo.md), а не в списке исправленного.

## Unreleased

### 2026-10-21 — LK-05: ручное восстановление воспроизведения по сети

- `AudioPlayer.error` теперь передаёт `AudioPlayerError(requestId, reason, message)`, а `load` принимает ID запроса. Причины различают отсутствие/неполноту локального объекта, временный сбой storage, ошибку источника и запрет autoplay. Web storage помечает подтверждённо отсутствующий/неполный объект отдельным JS-исключением `LocalAudioUnavailableError`.
- При потере локального объекта показывается «Воспроизвести по сети». Сетевой источник загружается и запускается только в обработчике нажатия, без автоматического переключения. Интерфейс показывает «Аудио по сети». Исходная ссылка в SQLite сохраняется, дополнительных записей контента нет.
- Ошибки другого ID загрузки игнорируются, в том числе во время открытия следующего видео. Web-плеер создаёт отдельный HTMLAudioElement для нового источника и снимает обработчики старого; запоздавшие media events и Promise-ответы защищены поколением загрузки.
- Ошибка remote заканчивается сообщением без цикла; явный RETRY сохраняет выбранный сетевой источник. Запрет autoplay и временная ошибка storage не предлагают fallback и не стирают локальную ссылку.
- Добавлены шесть common-тестов состояния/ID/повторов, browser-тесты причины ошибки и замены источника, а также сценарии настоящего интерфейса с удалением только аудио, сетевым воспроизведением и ответом media 503. После ошибки Web-источника сбрасываются состояние PLAY/PAUSE и таймер.
- Проверено: 75 JVM-тестов (44 shared, 31 backend), 34 Kotlin-теста в Chromium, три storage-сценария, development/production-сборки и сценарии приложения/миграции/fallback на обеих сборках. Сетевой YouTube-импорт после LK-05 не повторялся; media 503 и успешное сетевое воспроизведение проверены локальным fixture-сервером.
- Android-адаптер приведён к тому же контракту; проверка Android SDK/устройства остаётся отложенной, как и раньше.
- Использованы существующие MVVM и платформенный Adapter; отдельный автоматический Retry/Chain of Responsibility не вводился. [UML LK-05](docs/CHANGELOG_UML.md#lk-05).

### 2026-10-21 — LK-06: защита загрузки аудио по MIME

- Исправлено: успешные HTML/JSON/text и другие явно неподходящие Content-Type отклоняются в `ContentApi.download` до вызова audio storage. Добавлено исключение `UnexpectedAudioContentTypeException` с полученным MIME.
- Совместимость: допускаются `audio/*`, `application/ogg`, `application/octet-stream` и отсутствие MIME. Префикс и тело потока не читаются проверкой и передаются storage без изменений. Это проверка типа ответа, не валидация контейнера/кодека; поддельный или отсутствующий MIME остаётся отдельным направлением усиления.
- Backend явно отдаёт Opus в Ogg-контейнере с `Content-Type: audio/ogg`, включая ответ Range 206.
- Добавлены проверки отклонения HTML/JSON с HTTP 200 до сохранения, допустимых MIME с параметрами и сохранности байтов; существующий тест ответа без MIME сохранён. HTTP-тест проверяет тип обычного ответа и Range.
- Тест на успешный HTML-ответ воспроизвёл дефект до исправления. Срез проверки LK-06: 69 JVM-тестов (38 shared, 31 backend), 26 Kotlin-тестов в Chromium, development-сборка и сценарий приложения/миграции. Последующая проверка production и расширенной регрессии выполнена вместе с LK-05 выше.
- Архитектура: проверка добавлена в существующий HTTP Adapter; новый паттерн или зависимость не вводились. [UML LK-06](docs/CHANGELOG_UML.md#lk-06).
